## 1. 安装

文章给的安装方式：

```
npx skills add alchaincyf/huashu-design
```

本机实测：`git clone https://github.com/alchaincyf/huashu-design` 直接失败——

```
error: RPC failed; curl 28 Failed to connect to github.com:443 after 21051 ms
```

同一时刻 `codeload.github.com` 与 `api.github.com` 都通。改走 tar.gz：

```bash
curl -L -o huashu.tar.gz https://codeload.github.com/alchaincyf/huashu-design/tar.gz/refs/heads/master
# 37 MB / 426 个文件 / 解开后 assets 40 MB（84 张样张 + 6 段 BGM + 37 个 SFX）
```

解到 `~/.workbuddy/skills/huashu-design` 后 `npm install` 装了 30 个包（45 秒）。
`SKILL.md` 行数核过：**215 行**，与文章说法一致；`references/` 39 份 + `modules/` 4 份按需加载。

**结论**：安装不是「一条命令」，网络环境决定了必须走 codeload。

## 2. T1 开工三件事

三条命令都跑通了，但**文档与 CLI 不一致**：

| 命令 | 文档写的 | 实际必填 |
|---|---|---|
| `learn.py add --kind preference "<文本>"` | 就这一行 | 还要 `--topics`、`--evidence`，且文本里必须有「…」包住的用户原话 |
| `design_lint.py ledger add <f> --project x` | 一致 | 一致 |
| `capabilities.py` | 一致 | 一致 |

按文档抄，`learn.py` 会连续失败三次，报错依次是：

```
learn.py add: error: the following arguments are required: --topics
learn.py add 需要 --evidence：原话、项目和文件、测量结果——没人能核对上的条目只是传言
preference 必须引用用户原话：用「…」或 "…" 括起来
```

第三个校验很好——它挡住了「我替他总结他的品味」这件事。最终写成功的形式：

```bash
python "$HD/scripts/learn.py" add --kind preference \
  --topics "封面 巨字 色块" --project boids-explainer \
  --evidence "2026-10-24 本机实测：dir-2 与 dir-3 对比后选择" \
  "用户原话：「这个完全不 AI 感」。巨字敢放到 148px（适用范围：说明页封面区，不外溢到 App 界面）"
```

回读时，范围和原话都被完整带出，且标了 `L1 · 2026-10-24 · preference`。

**另一处假阴性**：`capabilities.py` 只扫 `~/.claude/skills`、`~/.agents/skills`、`~/.codex/skills`、
`~/.cursor/skills`、`.claude/skills`、`.agents/skills`——**不认 WorkBuddy 的 `~/.workbuddy/skills`**。
本机装了 `jimeng-suite`、`art-motion` 等兄弟技能，它一律报「兄弟 skill：没有 / 素材档位 T0」。
按它降级素材方案是错的。

## 5. T5 deck → PDF → 可编辑 PPTX

### PDF：通
```bash
node export_deck_stage_pdf.mjs --html deck.html --out deck.pdf
→ ✓ 412 KB, 5 pages, vector
```
（前提：node 侧的 chromium/ffmpeg 先补齐，见 §7。上游脚本自己写死的 `chromium.launch()` 在本机第一步就崩。）

### PPTX：第一次导，5 页里 4 页丢字
```bash
python pptx_from_rendered.py deck.html -o deck.pptx --selector "deck-stage section" --bg f6f4ef
→ 📐 量到 5 页 {'shape': 27, 'text': 5}
→ ⚠️ 丢字校验：4 处文字在浏览器里看得见、PPTX 里没有
   第 2 页缺：测试条件四套栈，同一份脚本 stack01remotion核心…
```

原因：`<deck-stage>` 的 shadow CSS 把非 active 的 `<section>` 设成 `display:none`，
它们在浏览器里没有布局盒，量坐标的脚本自然量不到。

**上游的丢字校验是有效的**——它当场把这 4 页点名了。文章说「顺手修了 PPTX 导出丢字的 bug」，
修的是校验能力，不是这条路径本身。

### 修法：先 flatten
```bash
python flatten_deck.py deck.html -o deck-flat.html       # 换掉外壳 / 移除 deck_stage.js / section 全 flex
python pptx_from_rendered.py deck-flat.html -o deck.pptx --selector "section" --bg f6f4ef
→ 📐 量到 5 页 {'shape': 27, 'text': 55}
→ 🔍 丢字校验：渲染后的页面文字全部在 PPTX 里，没有丢字
```

### 复核（不打开 PowerPoint）
```bash
python verify_pptx.py deck.pptx --html deck-flat.html
→ 页数 5；画布 26.67×15.00 in
   P1..P5：有字文本框 5/19/12/13/6，文本 run 6/24/13/18/13，合计 55
→ OK 与源 HTML 逐页比对：没有丢字
```
同一个脚本跑坏版本（`deck-bad.pptx`）：
```
→ 🔴 第 [2, 3, 4, 5] 页没有任何文字（整页变成图/空白）
```
说明复核是有效的，不是「永远报 OK」。

### 可编辑 ≠ 1:1 保真（交付前必须说）
用 WPS 打开 `deck.pptx` 并导出每页 PNG（`05-deck/wps-export/`）：文件能正常打开、无修复提示、文字是对象。
但版式会偏：`Remotion + GSAP + Three` 与 `HyperFrames` 撞在一起、页脚 `同一脚本 · 同一素材 · 同一输出规格02 / 05` 粘连。

两个原因：
1. `--font-ea` 默认「微软雅黑」，设计里用的是 Google Fonts 的思源宋体 → 本机没装 → 字宽全变；
2. 文本框宽度来自渲染时量到的 rect，字体一换就挤或撞。

→ **对外的定稿给 PDF（1:1、矢量可搜），要改稿给 PPTX 并说明是近似版。**
加 `white-space:nowrap` 只能救短标签，救不了正文重排。

## 6. T6 / T9 / T10 体检与记忆

### 坏样例（`09-ledger-lint/bad-example.html`，故意做坏）
```

🟡 01/02/03 编号 3 个——内容真是序列吗？
🟡 标题字体是 Inter（UI 小字体当 display）
```
裂图、控制台报错、对比度、模板装饰全部抓到。

### 真作品体检：可读性底线的冲突
三版完整稿第一次跑 check，全部红灯，主要是「HUD 微字」：
- dir-1：23 处标签低于 12px（等宽 10–11px）、2 处正文低于 14px、2 处对比度 4.28
- dir-2：24 处标签、7 处正文（13.5px）、17 处对比度 4.07
- dir-3：24 处标签（9.5–10px）、11 处正文、3 处对比度 2.46

抬到正文 14px / 标签 12px / 对比度 ≥4.5 后全绿。代价是所有「仪器读数感」「密排小字」都变粗一档。
**这是口径，不是 bug**：想要那种风格就得抬字号再谈风格。

### compare 抓到撞版，而且阈值反直觉
```
dir-2 ↔ dir-3：色板距离 0.026 → 撞了：色板几乎相同
```
暖纸 `#F4F1EA` 与灰纸 `#DDD7CC` 在它眼里是一回事。中间试过加三色大面积色块（→0.039）、
黑底裱框（→0.087 且被判成「深色」），最后换到牛皮纸 `#CDBFA4` + 中明度底 `#B9AB90` 才到 **0.146** 过线。
教训：撞版要靠**换材料或换骨架**，改一个色号糊不过去；但阈值给人的直觉是反的。

### 三版同族是 🟡 不是 🔴
三版最终都带 1px 细线 + 零圆角（「细线报纸」家族），`compare` 给的是提示不是红灯。
科学说明页题材下这是合理选择，按上游口径在交付说明里写理由即可。

## 7. T7 动效：上游脚本不通，改用逐帧渲染

### 上游 `render-video.js` 的三次失败
```
▸ Warmup (caching fonts)… / ▸ Recording (clean start)…
▸ Ready at 1.25s (from window.__ready)
✗ No webm produced
```
试过：bundled chromium、`channel:'chrome'`、补 ffmpeg 1011 —— 三次都停在同一步，
临时目录里没有任何 .webm。`__ready` 信号是被正确识别的，坏在 recordVideo 本身。

### 兜底：逐帧截图 + ffmpeg
HTML 侧三个钩子：
```js
window.__step  = () => { /* 推进一帧 */ return true; };
window.__setT  = (t) => { /* 按第 t 秒设文字状态 */ return true; };
document.fonts.ready.then(() => requestAnimationFrame(() => { window.__ready = true; }));
```
```
帧 180 张，用时 42.7s
✓ anim6s.mp4  1.11 MB  1920x1080 @30fps  6.0s
```
代价是 180 帧 43 秒（比 recordVideo 慢），换到的是帧级确定性：同 HTML 同输出，与机器时钟无关。

## 8. T11 事实先核实：机制真的能救

文章说 2.0 定的规矩是「涉及事实第一步先搜」。实测这条规矩救了两处：

1. **年份**。Reynolds 的论文常被写成 1986。搜到 SIGGRAPH 历史档案原文：
   *Computer Graphics* 21(4), Proceedings of SIGGRAPH'87 (Anaheim, July 27–31, 1987), pp. 25–34。
   1986 是早期演示的年份。三版 deck/页面统一写 1987。
2. **表述**。「凝聚拉满 → 漩涡」在纯三条规则下不成立（见 §3 校准实验），改写成「收成一团」+ 补充条件。

第二处不是搜索发现的，是**实测证伪**——但它证明同一个态度：图/数里没出现的东西不能写。

## 9. 环境：四套版本号互不相干（本机最耗时的坑）

| 组件 | python 侧 | node 侧 | 症状 |
|---|---|---|---|
| browser | `chromium-1248` | `chromium-1217` | `Executable doesn't exist at ...chromium-1217...` |
| ffmpeg | `ffmpeg-1013` | `ffmpeg-1011` | 同上，换成 ffmpeg 路径 |

上游 SKILL.md 只写 `pip install playwright && playwright install chromium`。
实际要 python 侧 + node 侧各一份，且 node 侧那份还必须**版本号对得上**。
本机实测 `npx playwright install` 下载被限速到 20 分钟量级，最终用目录联接补齐：

```
mklink /J %LOCALAPPDATA%\ms-playwright\chromium-1217 %LOCALAPPDATA%\ms-playwright\chromium-1248
copy %LOCALAPPDATA%\ms-playwright\ffmpeg-1013\ffmpeg-win64.exe %LOCALAPPDATA%\ms-playwright\ffmpeg-1011\
```

另外：上游 `scripts/*.mjs` 是 ESM，`NODE_PATH` 对它无效——在项目目录里直接跑会 `ERR_MODULE_NOT_FOUND`，
要在项目目录建 `node_modules` 联接指向 skill 的 `node_modules`。

## 10. 沉淀下来的东西

### 四条可复用的修法（已做成脚本）
| 脚本 | 解决 |
|---|---|
| `doctor.py` | 六项环境体检 + `--fix` 用联接补齐版本号 |
| `flatten_deck.py` | 单文件 deck → PPTX 丢字（5 页 4 页 → 0 页） |

| `rec_harness.py` | 取证录屏（最大化+置顶、ASCII 路径、chcp 65001） |

### 三条方法论级的收获
1. **缩略图阶段改版最便宜**。六格 480×300 的草稿救回三次返工（三栏溢出、中段空、两张撞同一构图）。
2. **图上没出现的东西不能写**。漩涡是写出来的，不是算出来的——校准实验把文案拉回事实。
3. **可读性底线不豁免风格**。微字美学的代价是必红，提前讲清楚，别在被问「为什么字这么小」时才解释。
